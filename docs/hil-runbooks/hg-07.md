# HG-07 — real Edge Core package and probe

Owner: [#4](https://github.com/01rabbit/Azazel-Nexus/issues/4), explicit child
work; dedicated child issue number unassigned.
Status: **not run; hardware-unverified**.

Use the [campaign](../hil-campaign.md) and
[Edge package verification contract](../edge-package-verification.md).
This exercises the actual producer artifact, installed binary, systemd and
Nexus consumer together. It does not establish package authenticity: the pinned
Edge manifest is unsigned. It grants no enforcement or activation authority.

1. Obtain the real Edge package produced by Azazel-Edge's
   `packaging/nexus-core/nexus_core_package.py`, with exact producer revision,
   pinned contract/version and build provenance. Install by the approved
   deployment path at the fixed package location. Never substitute a
   test-written package, health script or fake unit reader.
2. Record artifact/image digests and acquisition method without raw inventory.
   Verify package presence, pinned version, archive digest and unpacked binary
   digest before executing it. A mismatch is a security finding: stop, retain
   it, and do not rewrite the manifest to match the file.
3. Through the supported deployment/activation workflow, run `az-edge-probed`
   against the actual `azazel-edge-core --health` and real system-manager D-Bus
   state. Do not manually unmask a governed unit to bypass unavailable bootstrap
   or activation prerequisites. If the workflow is blocked, mark the exercise
   incomplete, not passed. Health must exit zero, parse under the pinned
   contract, say healthy and match the pinned version; running is a separate
   observation, not inferred from a one-shot health answer.
4. Read `azazel-nexus status` while the probe is fresh and bound to the same
   package version/digest. Retain all five findings: package, version, digest,
   health, running. Only all five passing can support `edge-baseline-ready`.
   Record freshness and its readback time; stale/mismatched/unverifiable probe
   state supplies no readiness, even if a prior run succeeded.
5. Retain the anonymous DUT/class/boot, installed tuple, sanitised health/probe
   and status observations and acquisition methods. Attest and validate the
   HG-07 record with the `azazel_nexus.hil_records.validate_record` (`azazel-nexus/hil-gate/v1`), per
   [evidence records](../hil-evidence-records.md).

Failure leaves readiness withheld. Preserve the artifact and findings; restore
only via the approved reviewed deployment/recovery path. Do not repair evidence
in place or start Edge through a manifest-supplied command. A passing package
probe does not establish HG-05 load readiness: that separately requires all
mandatory subsystem units and azazel.slice doing actual work under load.
