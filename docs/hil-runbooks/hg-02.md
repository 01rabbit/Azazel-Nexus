# HG-02 — daemon identities cannot unmask

Owner: [#115](https://github.com/01rabbit/Azazel-Nexus/issues/115) pilot,
[#4](https://github.com/01rabbit/Azazel-Nexus/issues/4) campaign.
Status: **not run; hardware-unverified**.

This is a disruptive **negative test**: refusal is the expected success
criterion. Use the [campaign](../hil-campaign.md) approvals, local console,
isolated test links and [protected evidence rules](../hil-evidence-records.md).
Do not implement this as a read-only acquisition tool.

1. Use package-created daemon accounts, including `azcommission`, `azaudit`,
   `azwatch` and every additional non-controller daemon account in the installed
   unit inventory. Record effective UID/GID, supplementary groups, capability
   and policy context by approved principal labels, without exporting personal
   or raw host inventory. Root is the activation-controller exception, not a
   daemon identity for which refusal is expected.
2. Before **each attempt**, verify a real installed operational target is masked
   and inactive using the HG-01 procedure. Use `azazel-commissiond.service` as
   the initial target and repeat over the installed governed operational set.
   Missing targets and already-unmasked targets are invalid tests. No activation
   request/grant may be pending; prevent controller races through the approved
   maintenance state, without granting the tested principal extra privileges.
3. From the root recovery console launch only the test client as the package
   daemon account, without a login session, retained root capabilities, delegated
   sudo/polkit authorisation, authentication agent or credentials. For example,
   substitute the package-created account for `DAEMON_ACCOUNT` below (not root):

   ```sh
   runuser -u DAEMON_ACCOUNT -- systemctl --system --no-ask-password unmask azazel-commissiond.service
   ```

   `runuser` is the root supervisor's identity switch; **systemctl must execute
   as the daemon**, without sudo. The target is the system manager, never a
   per-user manager. Do not respond to an authentication prompt or retry with
   elevated credentials. A prompt makes the unattended refusal test incomplete.
   An identity-equivalent client tests the account boundary; additionally test
   within the actual unit confinement when the approved harness supports it,
   recording the context separately. Do not claim the account test exercised
   service sandbox settings it did not enter.
4. Expect a nonzero permission refusal **and** an unchanged masked, inactive
   target. Record exit status, classified refusal and independently read back
   state immediately. Missing command, missing bus, unknown unit or unavailable
   systemd is `not-run`, not a permission-boundary pass. Exit status alone does
   not establish refusal: `unmask` may exit successfully without changing state.
5. **If the command exits zero or the target becomes unmasked, stop the
   campaign and record failure. Do not start or enable the target.** From the
   root recovery console, restore the pre-test safe state explicitly:

   ```sh
   systemctl --system stop azazel-commissiond.service
   systemctl --system disable azazel-commissiond.service
   systemctl --system mask azazel-commissiond.service
   systemctl --system is-enabled azazel-commissiond.service
   systemctl --system is-active azazel-commissiond.service
   ```

   For another tested target, substitute that exact installed unit throughout.
   Independently verify `masked` and inactive, no remaining enablement links,
   and no operational exposure/packets. Preserve the original result and all
   restoration results. A masking failure, unexpected start or uncertain state
   requires continued physical isolation and operator recovery; do not proceed
   or report a pass. A successful command with unchanged state still fails this
   strict expected-refusal test and needs investigation.
6. Repeat only from the restored, verified masked state for each account/target
   pair, including after a package-created-account reboot. Keep the per-pair
   acquisition context and outcomes; sanitise, attest and validate the HG-02
   record using the `azazel_nexus.hil_records.validate_record` (`azazel-nexus/hil-gate/v1`).

A complete refusal matrix establishes the exercised OS account/policy boundary
on this image. It does not exclude every other privileged principal, prove
controller authorisation correctness, constrain a hostile root owner, or prove
an untested service sandbox. Static Python token checks alone prove none of
the running-host privilege boundary.
