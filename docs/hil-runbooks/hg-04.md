# HG-04 — commissioning and permanent-identity continuity

Owner: [#115](https://github.com/01rabbit/Azazel-Nexus/issues/115) pilot,
[#4](https://github.com/01rabbit/Azazel-Nexus/issues/4) campaign.
Status: **not run; hardware-unverified**.

Follow the [campaign](../hil-campaign.md), [commissioning](../commissioning.md)
and [confidentiality rule](../inventory-confidentiality.md). This tests real
NIC/driver identity acquisition and the supported operator workflow. It does
not prove zero transmission, activation eligibility, or authoritative promotion
where that path is still unavailable.

1. Confirm encrypted commissioning storage, the protected on-device key and
   operator A/B prerequisites. Use the HG-04 read-only acquisition command
   **added in this change**, linked under [tools](../hil-evidence-records.md#tools-and-trust),
   to report permanent-identity availability from `IFLA_PERM_ADDRESS`. It must
   anonymise identity before any outward output. Raw netlink/inventory dumps
   belong only in the encrypted commissioning record. Keep kernel/driver
   provenance protected and export only approved HMAC references/class facts.
2. Run the installed commissioning workflow (`azazel-nexus commission` and its
   documented runtime adapter) under the package-created service account via
   the supported bootstrap path. If bootstrap, signature verification or
   authoritative persistence is unavailable, record the exact classified gap
   and stop; no manual unmasking, record editing or unsigned promotion.
3. Have the operator explicitly confirm each management/observation role and
   every unused interface. Preserve observations A separately from decisions B.
   Verify that unreadable/ambiguous permanent identity refuses a role rather
   than falling back to a current MAC, interface name, link or default route.
   Record real unreadability when encountered; do not modify physical identity
   to make a positive test pass.
4. Complete the supported signed-record workflow without hand-editing. A role
   draft or unsigned Fabric proposal is not authoritative commissioning or an
   activation grant. Retain its actual lifecycle stage and refusal if incomplete.
5. Reboot through the approved procedure. Use a supported adapter-renaming
   exercise if available and confirm composite identity still binds the same
   physical ports. Do not move/swap hardware and call it mere renaming. If no
   rename occurred, continuity across rename remains unverified. Check that
   changed/ambiguous composites withdraw affected eligibility rather than
   rebinding. Repeat read-only acquisition against the same protected reference.
6. Retain before/after boot fingerprints, anonymous DUT, acquisition method,
   per-role availability/continuity outcomes and operator approvals. Sanitise,
   attest and validate the HG-04 record with the HIL gate validator **added in
   this change**. Never export the raw composite or a raw record copy.

Identity drift, unexpected role inference or any need to hand-edit stops the
exercise. Keep affected services masked and return to commissioning through the
approved maintenance workflow; preserve failure records and restore only through
a new reviewed generation. Passing the NIC acquisition portion does not pass
the end-to-end gate if production bootstrap/promotion is blocked.
