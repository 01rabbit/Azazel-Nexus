## 10. Steps I cannot determine from the code, or where something else may happen
1. TIMING. TimeoutStartSec=30s covers the whole run because READY is never sent. Run 4 measured 15:02:59 to 15:03:10 (about 11 s) ending in BootstrapContainmentFailed, with two Reloads 9.5 s apart. That gap is dominated by admission (verify about 1.8 s, retain verify about 1.8 s, two `_check()` about 2.2 s each, generation admission about 0.4 s). Individual Reload latency and the cost of the extra close/observation in step 5.6 and the second narrow() in 7.3 are not measured. Estimated 12-20 s, unproven.
2. FragmentPath of a LOADED masked stub. After StopUnit (5.3) systemd loads a masked stub that may later be GC'd. The close fence expects `/etc/systemd/system/<unit>` and compares it with `LoadState=masked` snapshots (`same_closure` ignores only the loaded flag). I cannot tell from code what systemd 257.13 reports for FragmentPath of a loaded unit masked by an /etc symlink to /dev/null. Evidence: the first `_contain` in run 4 ran the same sequence on the same host state and did not raise, so it is empirically supported, but loaded versus not loaded is not deterministic.
3. MaskUnitFiles on an already masked link. The stamps include mtime and ctime of the symlinks (bootstrap_overlay_files.py:109-134,142). I expect systemd to leave an identical link untouched; if it re-creates it, `initial bootstrap baseline changed` refuses at 5.5 or 5.10. Same sequence already passed in run 4 (first `_contain`).
4. StopUnit on a masked, not-loaded unit must return a job that emits JobRemoved "done" (5.3). Assumed from run 4, not independently verified.
5. The exact shape of the final withdraw_pair (full close with Reload vs inspector only, see 5.6). Also whether it keeps `_containment_files` the initial-mode closed files and the same owner pin; the final confirm_empty_pair depends on it.
6. Other CORE_UNITS. `narrow()` (1.4, 7.3) masks watchdog, edge-probed and model-fetchd too. Their host state is not given; if not previously masked, narrow() creates /etc/systemd/system/<unit> -> /dev/null for them with no Reload. Harmless for the pair but changes host files. 7. `release_after_stop` can raise ApprovalRefused("bootstrap kernel deadline release refused") if `timer_delete` fails; that would REPLACE the original exception (bootstrap.py:942 inside the except block), changing the stderr text to `ApprovalRefused` (exit still 1). I expect success.

9. Containment is complete before the entrypoint narrows again (7.3), so a failure in that second narrow() does not change the grant record (already `closed`) but adds the EMERGENCY_UNCONFIRMED stderr line.
