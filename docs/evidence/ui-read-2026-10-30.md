# UI 用の読取経路（ADR-0007）の systemd 予行と実ブラウザ確認：2026-10-30

**コンテナ内の systemd と headless Chromium：VM でも実機でもない。** HIL の証跡ではなく、HG の欄にも
載せない。対象は [ADR-0007](../adr/0007-ui-read-leaves.md)（S-03・S-04）と [読取専用 UI](../operator-ui.md)。
画像・判定の原本・使ったスクリプトは [`ui-read-2026-10-30/`](ui-read-2026-10-30/) にある。

## 条件

| 項目 | 内容 |
| --- | --- |
| ノード | colima（Apple Silicon、ネイティブ aarch64）の特権 Debian trixie コンテナ（`--network` は既定の bridge。導入の pip にだけ使った）。systemd 257 が PID 1。カーネルは colima VM のもの |
| 導入 | 本番と同じ手順：`/opt/azazel-nexus/venv` に `pip install . ./runtime`（Python 3.13.5）、`env PYTHON=/opt/azazel-nexus/venv/bin/python sh packaging/install.sh`。uid・gid・mode はすべて installer が作ったまま |
| 有効化 | `systemctl enable --now azazel-noc-observe.timer azazel-units-observe.timer azazel-ui.socket`。運用者は `useradd -G azazel-operator` で作った 1 人 |
| ブラウザ | 別コンテナの Chromium 156.0.8078.73（Debian trixie、headless、`--no-sandbox`、uid 1001）。ノードのネットワーク名前空間を共有し（`--network container:`）、`127.0.0.1:8443` の `azazel-ui.socket` に接続。DevTools は pipe（ポートを開かない）。駆動部は [前回のハーネス](ui-browser-2026-10-29/harness.py) を再利用（[`shoot.py`](ui-read-2026-10-30/shoot.py)） |
| ログイン | 毎回、UI が書いた実際のコードを `azazel-operator` の利用者が読み、`Input.insertText` で入力。コードは記録・画像に残していない |

**入力は何か。** 実際に動いたのは installer が入れた `azazel-noc-observe`・`azazel-units-observe`（本番 unit、
サンドボックスつき）と `azazel-ui`（ソケット起動）だけ。ほかの daemon は install.sh のとおり masked のまま。
そのため Edge loop・auditd・Knowledge Lite・M.I.O. の snapshot は、**各書き手のアカウント**（`runuser -u azintake` など）
で製品の `UiCopy` と同じ書き方で書いた fixture である（[`write_as.py`](ui-read-2026-10-30/write_as.py)、内容は
[`gen_inputs.py`](ui-read-2026-10-30/gen_inputs.py) が製品と試験の生成関数で作ったもの。時刻だけ現在へずらした）。
Knowledge Lite の snapshot は、trust の無いこのノードで daemon が書く内容（`unavailable` / `trust_unreadable`）にそろえた。
インシデント 3 件（未解決 2 件、うち AI の説明 1 件）は試験用の固定データで、実際の攻撃ではない。

この予行で見つけて直したもの：entryd が記録する local 経路の語は `not_admitted` などで、`local_` の接頭辞は付かない。
読取 adapter が接頭辞付きを期待していたため、通常状態の提供元の理由が `local_observation_invalid` になっていた。
adapter を記録の語（`mio_status.HEALTH_REASONS`）に合わせ、全語を試す回帰試験を足した
（`test_the_adapter_reads_the_admission_record_from_entryds_snapshot`）。

## 手順（再現）

1. イメージ：`debian:trixie` に `systemd systemd-sysv dbus python3 python3-venv python3-dev gcc libc6-dev apparmor iproute2 openssl ca-certificates procps`（ノード用）、
   `chromium fonts-noto-cjk fonts-dejavu-core python3 python3-pil`（ブラウザ用）。作成時のみネットワークあり。
2. `docker --context colima run -d --privileged --cgroupns=host -v /sys/fs/cgroup:/sys/fs/cgroup:rw --tmpfs /run --tmpfs /run/lock -v <clone>:/src:ro <ノード用>`。
   コンテナ内で clone を写し、venv に `pip install . ./runtime`、`env PYTHON=/opt/azazel-nexus/venv/bin/python sh packaging/install.sh`。
3. `systemctl start azazel-noc-observe.service azazel-units-observe.service`、`cmp run/noc-status/status.json run/ui-read/noc/status.json`。
4. `bash write_all.sh`（各書き手のアカウントで写しを書く）、`runuser -u azui -- python azui_reach.py`、
   `runuser -u azui -- azazel-nexus --snapshot-reader ui status --json`（と `operator`）。
5. `systemctl enable --now azazel-noc-observe.timer azazel-units-observe.timer azazel-ui.socket`。Edge loop の写しを 5 秒ごとに書き直しながら
   `shoot.py --label normal overview incidents detail setup`、`--narrow overview`。`degrade.sh` の後に `--label degraded`、
   `perm.sh` の後に `--label denied`。

## これが示さないもの

- **実機ではない。VM でもない。** 実 NIC・実記憶域・再起動・性能・物理分離は何も示さない。x86_64 では実行していない。
- Edge・auditd・Knowledge Lite・M.I.O. の daemon は動いていない（masked）。それらの写しは書き手のアカウントで書いた fixture で、
  daemon が書いたものではない（書き方は daemon と同じ `UiCopy`。daemon の書込み経路は単体試験で確かめた）。
- インシデントは試験用の固定データ。AI の説明は記録済みの固定文で、モデルは動いていない。
- Mac の Chrome での手操作、キーボードだけの操作、タッチ、IME、画面読上げは確かめていない。
- 「権限不足」は leaf の group を手で変えて作った状態で、installer がそうするわけではない。
