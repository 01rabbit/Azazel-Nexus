## 結果の要約

- aarch64：pass 53 / fail 0 / skip 2。x86_64（Rosetta）：pass 55 / fail 0 / skip 2
  （Rosetta への適応と drop-in の後始末の 2 件が多い）。skip は両方とも
  「locald の応答改変」（admission が閉じていて locald は誰にも呼ばれない）と
  「Mission Pack の期限」（commissioning と HG-05 がなく、pack を ACTIVE にできない）。
- モデルなしの参照：entryd は operator の要求を `deterministic handoff` にし、explainer の記録は
  referenced の固定語 `mio_handoff:no_pack` と handoff の固定通知になった。referenced への
  operator の直接接続は `principal_denied`。
- Knowledge Lite：§11 の順に `trust_unreadable → unverified → no_bundle → available` を
  azknowledge 自身で確認し、knowledge-lited 経由で `T1110` が説明に引用された。
- 障害注入：SIGKILL・偽の応答（注入文やゴミ）・壊れた Edge 行・容量圧迫のいずれでも、
  他の unit と Edge Core（同じ PID）は動き続け、説明には固定の失敗コードだけが残った
  （偽 peer の文面は記録に入らない）。
- 再起動：activation pass は `granted=0`、手動の marker は残らず、手動で unmask した unit は
  すべて再び masked・inactive。marker なしの起動は `ConditionResult=no` で skip。
  再起動前に入れた Lite の撤回は `revoked` のまま。
