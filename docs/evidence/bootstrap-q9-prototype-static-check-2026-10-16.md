### 1.4 Caveats on (a)
1. The allowlist is not enforced at the generic layer. `BootstrapStopJobs._call` (R/bootstrap_stop.py:107-161) will send any `member` string; `SystemdUnitCalls` (R/systemd_bus.py:141-172) still contains live Unmask/Enable code paths. The PASS is a call-site audit, not a structural guarantee. Recommend a unit test that greps R/ for member literals against the table in 1.2 (the Q9 "pair it with a test" item).
2. Beyond the strict list, a full run uses StopUnit, CancelJob and MaskUnitFiles on exit paths (not forbidden by Q9's list but "any other method"). They are limited to the exact pair names (StopUnit/CancelJob) or the five CORE_UNITS (MaskUnitFiles in `narrow`).
3. `Reload` is a manager-wide daemon-reload, not unit-scoped. It is the intended publication step, but it also re-reads every unit file on the host (host-unknown, see U2).

E2. SIGTERM / SIGINT operator stop
 - Handler only sets an Event (R/bootstrap_lifetime.py:84-86). Observed at: `wait()` wake-up (:82), or any `_cancelled()` check (bootstrap.py:569-573, e.g. :590, :601, :619, :632, :688, :695, :721-:844).
 - If observed in the loop condition (bootstrap.py:851): loop ends, `_supervise` returns, `_finish_transaction` runs the C1-C6 sequence with `bootstrap.stopping` recorded first, grant -> `closed`, `_release_deadline_guard`, `BootstrapResult("stopped")`, `main` prints "supporting bootstrap stopped after confirmed containment" and returns 0 (R/activated.py:523-525).
 - If observed at a checkpoint during open_pair, READY or start: `ApprovalRefused("... cancelled")` -> exception route E1 (exit 1). A SIGTERM during a synchronous `check_start` is only honoured at the next `_cancelled()` call; a SIGTERM during `run_until_complete` in a bus session interrupts the select and the handler runs, but nothing aborts the in-flight job (job state is re-observed by containment).
 - With `systemctl stop azazel-activated.service` the real ordering is decided by systemd, not this code: both helpers declare `Requires=` + `BindsTo=` + `After=` the controller (R/hardening.py:~479-481 commissiond, ~506-508 auditd), so the manager stops the helpers FIRST and sends SIGTERM to the controller only after they are inactive (KillMode=control-group, TimeoutStopSec=10s, TimeoutStopFailureMode=kill, KillSignal=SIGTERM, packaging/systemd/azazel-activated.service). The controller then wakes with auditd already gone: `_record("bootstrap.stopping")` fails (peer proof or connect fails), `audit_error` is set, containment still runs, the grant is moved to `recovery_required` and the exit is 1 ("transaction close was not fully recorded"). Alternatively the 10 s poll sees `_ready` fail first (E1.7). Either way the clean "stopped, exit 0" outcome of the first bullet is only expected for a SIGTERM that is NOT preceded by systemd stopping the helpers (for example `kill -TERM <main pid>`). [U8]
 - Containment time versus `TimeoutStopSec=10s`: C1-C6 contains about 8 Reloads/drain/inspect sessions, 4 StopUnit calls and 2 `confirm_empty_pair`; the earlier narrowing-only `_contain` measured about 9.5 s between two Reloads (Gate A doc §10 item 1). If stop exceeds 10 s systemd sends SIGKILL (TimeoutStopFailureMode=kill) mid-containment [U9].

E3. Deadline expiry
 - E3.a Supervisor-detected (graceful): `_check()` (bootstrap.py:329-333 "elapsed clock invalid or expired"), loop `remaining <= 0` (:859-860), `_start_checkpoint`/`_intent_checkpoint` elapsed checks (:603-606, :634-637), `_heartbeat` sample (:876-878). Raises `ApprovalRefused` -> E1 route (exit 1) with containment first. Granularity: the loop checks at most every 10 s plus synchronous check time.
 - E3.b Kernel timer: `SIGKILL` of the controller at the absolute CLOCK_BOOTTIME deadline (R/_bootstrap_deadline.c:91-103; never disarmed except `release_after_stop`, R/bootstrap_kernel_deadline.py:65-77). No Python cleanup, no `bootstrap.stopping`, no withdrawal. State left behind: unit files in /run/systemd/system.control still non-empty if the kill landed before C1's truncate; journal in `published`/`closing`/`withdrawing`; grant record at its last phase; controller-used marker present (so `ConditionPathExists=!...` blocks a controller restart this boot); helpers follow-stopped by BindsTo (systemd's job) [U10]. Next boot: /run is empty, the /etc masks are intact, the persistent journal (never deleted, section 2.4) still says non-closed; the first `_contain` of the next boot goes through `resume_closure`/`_close_candidates_at` and refuses on the missing owned files (of:410-427 maps the OSError to ApprovalRefused), i.e. manual review (Q3's "journal with no files" case) [U10, U13].
 - WatchdogSec=30s expiry (WatchdogSignal=SIGKILL) is the same as E3.b but triggered by a missed heartbeat [U3].

## 6. Violations and findings list

Violations of Q9 (a) or (b): none found.

Findings to carry into Q8/Q7/Q4, in priority order:
1. U3 (timing): the 10 s READY deadline (mgr:926) against five `_check()`-bearing checkpoints, and the 10 s `_bounded` window against three synchronous start checkpoints, are likely to fail on the first real run by the repo's own measurements. Run 3 died on this class of defect.
2. U8: operator stop through systemd likely ends in `recovery_required` and exit 1 rather than a clean stop, because auditd is already stopped when `bootstrap.stopping` is recorded.
3. U9 / E3.b: 10 s TimeoutStopSec versus containment length; SIGKILL leaves a published or closing overlay plus a never-deleted journal.
4. 1.4: member allowlist is structural only at `SystemdBusSession._exchange` (and it still admits Unmask/Enable); `BootstrapStopJobs._call` accepts any member. A source-level test pinning the 1.2 table would turn this PASS into a regression guard.
5. 2.6: the controller sandbox `ReadWritePaths` are wider than the Q9 set, so the sandbox does not corroborate the claim.
6. Audit-record irreversibility (E1.6): grant_intent, controller_ready_intent, start_intent AUDITD are written before COMMISSIOND starts, so any failure after step 7 leaves permanent ledger entries and the once-per-boot marker consumed.
